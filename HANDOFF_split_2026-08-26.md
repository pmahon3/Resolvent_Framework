## 1. The task

The blueprint DAG has three components:

| size | what |
|---|---|
| 89 | query-system core, Stone/extension, Andersen–Jessen, delay, reconstruction, pruning |
| 43 | σ-essential: carrier, Ulam witness, blocks/patterns, inner regularity, the centre |
| 16 | the MO₂ descent ladder |

The 89/43 split is the one to attack. It has been called "structural" since the
first measurement, and correctly: **no σ-essential module imports the
query-system core, and none of the core imports σ-essential.** Verified
mechanically — each lane's transitive import reach contains nothing outside
itself. So there is no existing dependency to expose; a bridge must be *new
mathematics*.

## 2. The trivial route is banned, and here is why

On 2026-08-25 a module `Quarantine.lean` was written that did close this split,
and it was removed the same day. Do not re-walk it.

It proved: a query's outcome space carries a `MeasurableSpace`; σ-algebras are
intersection-closed; therefore `boolean_no_witness` forbids a σ-essential
witness on one. True, and the general statement is mildly worth knowing. But the
*edge* came from `delayQuery_no_witness`, a pure instantiation of the general
theorem at a delay object — it added nothing beyond naming a delay object inside
a σ-essential theorem, and removing the module put the component count straight
back, which is the proof that nothing but the naming held it.

**The standard this sets:** an edge must be a theorem in which the two lanes
*constrain each other*. A theorem whose statement merely mentions both sides is
not a bridge. If you find yourself instantiating a general result at an object
from the other lane, stop — that is the same mistake.

## 3. Why the lanes do not meet (the actual obstruction)

This is the thing to understand before proposing anything.

A `QuerySystem` posits a single space `Omega` of coherent families. Every
observable is a function on that one space, so the events `Cyl i A` are subsets
of one set, and `sigmaQ` — the σ-algebra they generate — is a **Boolean**
σ-algebra. The σ-essential lane's entire subject is a carrier that is a proper
**σ-class**: a Dynkin system that is *not* intersection-closed
(`carrier_not_interClosed`), because that is the only place a witness can live
(`boolean_no_witness`).

So any bridge of the form "take the query system's events as the σ-essential
carrier" is dead on arrival, and dead trivially. That is exactly what the
quarantine discovered without noticing it had discovered it.

**Therefore a real bridge has to break the assumption that produces the Boolean
algebra.** There are two ways, and only one of them is cheap.

## 4. The direction I would take

### 4.1 The observation

`UpperDirected` is a **predicate**, not a field of the `QuerySystem` structure
(`QuerySystem.lean`: the structure carries `ι, q, le, π` and the coherence laws;
directedness is `def UpperDirected : Prop := ∀ i j, ∃ k, le i k ∧ le j k`). So
**non-directed query systems are already legitimate objects** in the existing
formalization. Nothing needs to be redefined to talk about them.

Now: when is the cylinder family a π-system?

```
Cyl i A ∩ Cyl j B = { ω | ω.1 i ∈ A ∧ ω.1 j ∈ B }
```

If some `k` refines both `i` and `j`, this is again a cylinder at level `k`
(pull `A` and `B` back along the projections and intersect there). If no such
`k` exists, there is no reason for the intersection to be a cylinder at all.

**Directedness is exactly what makes the cylinders closed under intersection.**

### 4.2 The edge to prove first (should be short)

> If `S` is upper-directed, the **σ-class** generated by `CylGen` is
> intersection-closed, hence carries no σ-essential witness.

Chain: directed ⟹ `CylGen` is a π-system ⟹ (Dynkin's π–λ theorem) the σ-class
generated equals the σ-algebra generated ⟹ intersection-closed ⟹
`boolean_no_witness`.

**The π-system step is already verified** (2026-08-26, compiles against the
current build) — you are not starting from my assertion:

```lean
example (S : QuerySystem) (i j k : S.ι) (hik : S.le i k) (hjk : S.le j k)
    (A : Set ((S.q i).Outcome)) (B : Set ((S.q j).Outcome)) :
    S.Cyl i A ∩ S.Cyl j B
      = S.Cyl k ((S.π hik).π ⁻¹' A ∩ (S.π hjk).π ⁻¹' B) := by
  ext ω
  simp only [QuerySystem.Cyl, QuerySystem.eval, Set.mem_inter_iff,
    Set.mem_setOf_eq, Set.mem_preimage]
  rw [ω.2 hik, ω.2 hjk]
```

Coherence (`ω.2`) is what does it: `ω.1 i = π hik (ω.1 k)`, so both conditions
move to level `k`. What remains for §4.2 is the measurability of that
intersection (immediate — the `π` are `Refine`s, which bundle measurability) and
then the π–λ step.

This is a genuine implication between the two lanes' central predicates —
`UpperDirected` on one side, `IsSigmaEssential` on the other — and its content
is the π–λ step, not an instantiation. Mathlib has the π–λ machinery
(`MeasurableSpace.DynkinSystem`, `generate_eq` for π-systems); the repo already
uses `DynkinSystem` throughout, so the types line up.

**Read the contrapositive, because that is the payload:** a σ-essential witness
on a cylinder-generated carrier *requires the query system to be non-directed*.
That makes the failure of directedness — already the central object of chapters
1–3, and the thing `not_seqUpperDirected` and the Andersen–Jessen counterexample
are about — into a *necessary condition* for the σ-essential phenomenon. Two
lanes, one hypothesis, constraining each other in both directions.

### 4.3 The research question (the hard, open half)

> Does some non-directed query system's cylinder σ-class actually **fail** to be
> intersection-closed — and can it carry a witness?

Necessary is not sufficient. Non-directedness removes the reason the σ-class is
Boolean; it does not supply a witness. This is the real work, and it is on the
programme's own frontier: a positive answer would produce a σ-essential carrier
*from observational data*, which is what `Φ` and `PsiOML` are about.

Concrete first moves:

- The two non-trivial query systems in the repo are both **directed**, so
  neither can be the example: `delayQuerySystem.upperDirected` is proved, and
  the Andersen–Jessen system is indexed by `ℕ` with `≤`. You will have to build
  a non-directed one.
- Smallest interesting shape: two queries with no common refinement — i.e. a
  genuine pair of incompatible contexts. Check whether the σ-class generated by
  their cylinders is intersection-closed. If it *is* for every such small
  system, that is itself a result (and a negative one worth recording).
- `ConcreteOMLBlocks.lean` and `ConcreteOMLPatterns.lean` already carry the
  block/pattern layer on the σ-essential side; a query-system-generated OMP
  would want to land there.

## 5. Literature — do this before naming anything

The repo rule is **name things last**, and this area is crowded. What is
already recorded, and must not be rediscovered:

- `papers/reconstruction/notes/PRIOR_ART_VERDICT.md` is the lane's durable
  prior-art record. It establishes that **Abramsky–Brandenburger 2011**
  (NJP 13 113036, arXiv:1102.0264) *owns* the definitional core: presheaf
  compatibility = empirical adequacy, **global section = realisability**, and
  contextuality = the obstruction to a global section. Their §5 relates
  no-signalling to extendability by a *signed* measure.
- **Vorob'ev 1962** owns the exact iff for when every locally consistent family
  extends: regularity of the complex, equivalently α-acyclicity. **BFMY 1983**
  is the database mirror.

Why this matters here: "local consistency without a global section" is the
shared shape of *both* lanes — compatible marginals that do not extend (AJ) and
a finitely coherent pattern with no σ-additive extension (the witness). **That
unification is known.** So a bridge whose content is "both lanes are instances
of sheaf contextuality" is Type 6 at best and probably already published. The
directedness result in §4.2 is different in kind: it is a statement about *when
the carrier is Boolean*, which is a measure-theoretic/π–λ fact, not a
presheaf-theoretic one.

Also check before claiming anything about §4.3: the quantum-logic literature on
when a family of Boolean σ-algebras pastes into a non-Boolean OMP (Kalmbach,
Pták–Pulmannová, Navara) — the σ-essential lane already cites Binder–Navara and
Navara–Pták, so the neighbourhood is known to the programme, and the pasting
construction is standard. The question is whether *observational* pasting (query
systems) gives anything the abstract pasting does not.

## 6. What counts as success, what counts as failure

Declare types and bars **before** auditing (`notes/programme/contribution_evaluation.md`):

- §4.2 alone is most likely **Type 6** (translation) or a small **Type 1**. Its
  value is the contrapositive, and its bar is that the π–λ step is doing real
  work rather than dressing up `boolean_no_witness`. Be honest: if the proof
  reduces to "σ-algebras are intersection-closed", it is the quarantine again.
- §4.3, if it produces a witness, is **Type 1** and large. If it produces a
  proof that no cylinder σ-class can fail intersection-closure, that is
  **Type 5** — and a good one, because it would close the observational route to
  Φ permanently.

**A negative answer is a real result here.** Do not treat "no bridge found" as
failure to be worked around. The 89/43 split being genuinely unbridgeable would
itself be worth stating.

## 7. Discipline (the parts that have bitten this repo)

- **The standing hazard.** Statements that compile and prove nothing. Four in one
  week, each caught by reading a source rather than by a gate: a vacuous
  existentially-bound lemma; a "concreteness" predicate true of every
  `DynkinSystem`; a `full` field needing an undischargeable hypothesis; a
  docstring gloss that was not the source's definition. Before adding a node:
  *does the statement say what the paper says?* A clean axiom receipt does not
  answer that.
- **Check inhabitation.** An implication whose hypothesis is unsatisfiable proves
  nothing. The σ-essential open core sat over an unsatisfiable predicate for
  weeks, which made `TargetA_sharp` — a named conjecture — provably false. If
  you introduce a predicate, exhibit something satisfying it.
- **Edges follow the Lean, never the prose.** Add a `\uses` only when the proof
  actually consumes the thing. Two edges in this repo were added only after a
  refactor made them true.
- Never push without being asked. Blueprint changes need a re-render and a
  committed `lean_decls` in the same commit.
